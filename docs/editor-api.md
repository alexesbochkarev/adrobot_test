# HTTP API редактора

Все пути ниже имеют префикс `/api/v1`. ID кампаний, потоков и офферов в URL — ID Keitaro.
Ответ потока содержит отдельно локальный `id` и `keitaro_id`.

| Метод и путь | Действие |
| --- | --- |
| `GET /campaigns` | Доступные кампании Keitaro |
| `POST /campaigns/{id}/fetch` | Загрузить и сохранить потоки; запрещено при черновиках или блокировке |
| `GET /campaigns/{id}/streams` | Локальные потоки, черновики, архив и состояние блокировки |
| `POST /streams/{id}/offers` | Добавить оффер: `offer_id`, `expected_revision` |
| `POST /streams/{id}/offers/{offer_id}/remove` | Удалить из черновика |
| `POST /streams/{id}/offers/{offer_id}/restore` | Восстановить; проверить доступность оффера в Keitaro |
| `POST /streams/{id}/offers/{offer_id}/pin` | Закрепить текущую долю или переданное целое `share` |
| `POST /streams/{id}/offers/{offer_id}/unpin` | Снять закрепление |
| `POST /streams/{id}/cancel` | Вернуть подтверждённый снимок |
| `POST /streams/{id}/push` | Опубликовать черновик |
| `GET /publications/{uuid}` | Проверить журнал публикации |
| `POST /publications/{uuid}/reconcile` | Проверить неопределённую публикацию чтением, без повторного PUT |

Каждая правка и Push принимают JSON `{"expected_revision": 1}` с актуальной версией
потока. Для Push также обязателен UUID в заголовке `Idempotency-Key`.
Повтор успешной публикации с тем же ключом и версией возвращает сохранённый результат.
Устаревшие версии, конфликты и блокировки возвращают 409; неверные значения — 422.

## Fetch

Исчезнувшие из Keitaro связи сохраняются в архиве. Исчезнувший поток сохраняется с
`remote_present=false` и недоступен для правок. Закрепление сохраняется только тогда,
когда соответствующая доля не изменилась на сервере; иначе закрепление снимается.
Новые офферы импортируются без закрепления. Недоступное название заменяется на `Offer {id}`.
Потоки redirect/action показываются без разбора их офферов.

Импорт атомарный. Если за время запросов другой пользователь изменил локальную кампанию,
Fetch отклоняется. Некорректные доли, дубли и неактивные связи офферов отклоняются без
частичного импорта. После конфликта нужно отменить черновик и повторить Fetch.

## Push и сбои

Push сохраняет журнал и блокировку кампании до внешней записи. Далее он читает поток,
сравнивает его с последним Fetch, проверяет доступность офферов, отправляет
`PUT /streams/{id}` только с полем `offers` и проверяет результат повторным GET.
Фильтры, лендинги и прочие настройки в PUT не передаются. Из сравнения исключены
временные метки, а офферы сравниваются по ID, доле и состоянию.

При подтверждённом успехе снимок и журнал обновляются вместе, блокировка снимается.
При известном отказе или предварительном конфликте блокировка снимается, черновик остаётся.
При таймауте записи или ошибке последующей проверки статус — `unknown`; редактирование,
Cancel и Fetch этой кампании блокируются, чтобы не потерять незавершённую публикацию.

Reconcile выполняет только GET. Если результат точно совпал с ожидаемым, публикация
подтверждается и блокировка снимается. Иначе возвращается 409 и требуется ручная сверка.
Поддерживается также `pending/verifying` после сбоя БД при финальном сохранении.
`pending/checking` и `pending/updating` после аварийного завершения требуют ручной проверки;
автоматического освобождения таких блокировок нет. Не редактируйте sync_token до сверки
удалённого состояния и остановки незавершённых обработчиков.

У Keitaro в используемом контракте нет условного PUT по версии. Между предварительным
GET и PUT остаётся окно для внешней правки; гарантировать атомарную защиту от изменений
напрямую в админке нельзя. Последующая проверка выявляет расхождения, но не устраняет это окно.

## Проверка

На реальном экземпляре проверены список кампаний и Fetch. Реальный PUT редактора пока
не проверен; его успешные и аварийные сценарии покрыты HTTP-моками. Тесты также проверяют
конкурентные правки, идемпотентность, архив и миграцию с сохранением старых связей.
Миграция `0004` использует нативные изменения колонок; для её downgrade нужен SQLite >= 3.35.
