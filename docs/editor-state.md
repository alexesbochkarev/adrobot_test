# Локальное состояние редактора

Этап 3 реализует модели и сервисы, которые работают внутри транзакции SQLAlchemy.
HTTP API редактора, Fetch/Push и проверка внешних конфликтов подключены на этапе 4;
см. [editor-api.md](editor-api.md).
Ни один сервис этого этапа не вызывает Keitaro. Создание кампании из этапа 2 пока не заполняет
таблицы редактора: их первичное заполнение выполняет Fetch.

## Хранение

Миграция `0003` добавляет:

| Таблица | Назначение |
| --- | --- |
| `offers` | Локальный справочник: уникальный ID Keitaro и название |
| `streams` | Кампания, ID Keitaro, название, позиция, схема и версия состояния |
| `stream_offers` | Уникальная пара потока/оффера, текущие и подтверждённые значения |

У связи хранятся `share`, `pinned`, `removed` и снимок
`published_share`, `published_pinned`, `published_removed`.
`published_share = NULL` означает, что связь добавлена только в черновике.
Значения относятся к конкретному потоку: один оффер может иметь разные доли и статусы
в нескольких потоках.

`Stream.is_dirty` вычисляется сравнением со снимком; отдельный флаг в БД не хранится.
Сами черновики, снимки, закрепления и архив сохраняются в БД и переживают перезапуск приложения.

Удаление потока каскадно удаляет его связи. Справочник офферов при этом сохраняется.
Удалить оффер, на который ссылается связь, не позволяет внешний ключ.

## Операции

Все функции находятся в `src/adrobot/editor.py`. Идентификаторы офферов в аргументах
`remove_offer`, `restore_offer`, `pin_offer`, `unpin_offer` — **ID Keitaro**.

| Функция | Поведение |
| --- | --- |
| `new_imported_stream` | Подготавливает первый подтверждённый снимок без перерасчёта исходных долей |
| `add_offer` | Добавляет новую связь; архивную восстанавливает; активный дубликат отклоняет |
| `remove_offer` | Архивирует подтверждённую связь с 0%; никогда не опубликованную связь убирает |
| `restore_offer` | Возвращает архивную связь без закрепления и пересчитывает доли |
| `pin_offer` | Закрепляет текущую или явно заданную долю |
| `unpin_offer` | Снимает закрепление и перераспределяет остаток |
| `cancel` | Восстанавливает точные доли, закрепления и архив из последнего снимка; убирает новые связи |
| `publication_offers` | Готовит массив активных офферов для будущей публикации; не изменяет снимок |
| `acknowledge_publication` | Обновляет снимок после успешной внешней публикации именно этой версии |

После `remove_offer` связь остаётся в архиве и после `acknowledge_publication`.
Восстановление такой связи делает поток изменённым; Cancel возвращает её в архив.
Подготовка массива для отправки не является подтверждением публикации.

Функции не делают `commit` и не скрывают `rollback`: вызывающий код владеет транзакцией.
Отклонённая операция проверяется до изменения ORM-объектов и не оставляет частичный черновик.
После ошибки сохранения вызывающий код обязан откатить транзакцию.

Пример работы сервисного слоя с уже загруженным потоком:

```python
from sqlalchemy.orm import Session

from adrobot.editor import pin_offer
from adrobot.models import Stream

with Session(engine) as session, session.begin():
    stream = session.get(Stream, local_stream_id)
    pin_offer(stream, keitaro_offer_id, expected_revision=client_revision, share=25)
```

## Доли и принятые решения

Эти правила уточняют случаи, которые не раскрыты в видео:

- Доли — целые числа 0–100. У удалённого оффера всегда 0 и нет закрепления.
- Закреплённые доли сохраняются. Остаток от 100 делится поровну между активными
  незакреплёнными офферами; лишние процентные пункты получают меньшие ID Keitaro.
- Например: закреплено 25%, остальные два оффера получают 38% и 37%.
- Если закреплено 100%, незакреплённые офферы получают 0%. Нулевая активная доля разрешена.
- Если все активные офферы закреплены, их сумма должна быть ровно 100%; иное изменение отклоняется.
- Удалить последний активный оффер нельзя. Для возврата из нового черновика к изначально
  пустому потоку можно использовать Cancel.
- При удалении закрепление снимается. Restore возвращает оффер незакреплённым;
  Cancel восстанавливает закрепление, если оно было в подтверждённом снимке.
- Первичный импорт сохраняет исходные доли, в том числе неравные. Некорректный набор
  с дубликатами, дробными долями или суммой активных долей не 100 отклоняется.
- Пустой поток со схемой `landings` поддерживается; добавленный первый оффер получает 100%.
- Потоки `redirect` и `action` хранятся без разбора содержимого; редактирование их офферов запрещено.
- Add/Remove новой связи может оставить перераспределённые доли остальных офферов.
  Cancel всегда восстанавливает исходные доли точно, без нового перерасчёта.

Алгоритм вынесен в `src/adrobot/allocation.py` и не зависит от SQLAlchemy, HTTP или состояния БД.

## Конкурентные изменения

Каждая операция требует `expected_revision`. Устаревшая версия возвращает доменную ошибку
`stale_revision`. Фактическое изменение повышает `Stream.revision`; повтор операции,
которая уже ничего не меняет, оставляет версию прежней.

SQLAlchemy дополнительно проверяет версию при сохранении: из двух сессий, загрузивших
один поток, устаревшая получит `StaleDataError`; после rollback её изменения связей не сохранятся.
Работать со связями нужно через сервисы, а не через bulk UPDATE, который обходит эту проверку.

Это защита локальной БД. Она не заменяет проверку изменений непосредственно в Keitaro
и координацию записи по сети — эти части относятся к следующему этапу.
