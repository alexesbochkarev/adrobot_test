# Adrobot backend

Обёртка над Keitaro на FastAPI + SQLAlchemy. Разрабатывается поэтапно.

## Текущий этап

Готовы основа backend, клиент Keitaro, справочники, поиск офферов и создание кампании
с двумя потоками. Создание защищено ключом идемпотентности и журналируется в локальной БД.
Готов локальный сервис редактора: модели потоков/офферов, черновики, отмена, архив,
восстановление, закрепление и пересчёт долей, защита от конкурентных изменений.
HTTP API редактора и синхронизация Fetch/Push с Keitaro — следующий этап.
Правила и использование сервисов: [docs/editor-state.md](docs/editor-state.md).
Требования и следующие этапы описаны в [docs/backend-plan.md](docs/backend-plan.md).

## Запуск

Нужны Python 3.12–3.14 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Все команды выполняются из корня репозитория. Версии зависимостей зафиксированы в `uv.lock`.

```sh
uv sync --locked
cp .env.example .env
uv run --locked alembic upgrade head
uv run --locked uvicorn adrobot.main:create_app --factory --reload --host 127.0.0.1
```

По умолчанию используется SQLite, файл `adrobot.db` в текущей директории.
Приложение само не создаёт таблицы: миграции запускаются отдельно.
Секреты и локальная БД исключены из Git. Без настроек Keitaro работают health API и тесты;
интеграционные endpoints возвращают 503.

- Swagger UI: <http://127.0.0.1:8000/docs>
- OpenAPI: <http://127.0.0.1:8000/openapi.json>
- `GET /api/v1/health/live` — процесс отвечает.
- `GET /api/v1/health/ready` — БД доступна и необходимые таблицы существуют;
  без миграций возвращает 503. Это не проверка подключения к Keitaro.

Настройки читаются из `.env`; переменные окружения имеют приоритет:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_NAME` | `Adrobot API` | Заголовок OpenAPI |
| `DATABASE_URL` | `sqlite:///./adrobot.db` | SQLAlchemy URL базы |
| `KEITARO_BASE_URL` | не задан | HTTPS origin трекера, например `https://tracker.example.com` |
| `KEITARO_API_KEY` | не задан | Ключ Admin API; передаётся только в заголовке `Api-Key` |
| `KEITARO_DOMAIN_ID` | не задан | Домен создаваемых кампаний по умолчанию |
| `KEITARO_GROUP_ID` | не задан | Группа кампаний по умолчанию |
| `KEITARO_TRAFFIC_SOURCE_ID` | не задан | Источник трафика по умолчанию |

В этом этапе проверен SQLite. Другие СУБД требуют отдельного драйвера и проверки.

## API Keitaro

Контракт основан на [официальной документации](https://admin-api.docs.keitaro.io/)
и проверке ответов тестового экземпляра через GET-запросы.
Реальное создание кампании пока не проверено: автоматические тесты используют HTTPX MockTransport.

| Метод и путь (после `/api/v1`) | Назначение |
| --- | --- |
| `GET /reference/domains` | Активные домены |
| `GET /reference/groups` | Группы типа `campaigns` |
| `GET /reference/traffic-sources` | Активные источники |
| `GET /offers?q=123&limit=50` | Поиск активного оффера по ID или части имени |
| `POST /campaigns` | Создание кампании и двух потоков |
| `GET /campaign-creations/{uuid}` | Состояние операции, этап, удалённый ID и результат |

Поиск офферов получает доступный список из Keitaro и фильтрует его на backend;
не полагается на недокументированные параметры поиска upstream API.

Для `POST /campaigns` нужен заголовок `Idempotency-Key` с UUID. Пример тела:

```json
{
  "name": "Adrobot demo",
  "country_code": "AU",
  "offer_id": 123
}
```

Используйте реальный доступный ID оффера из справочника. Можно дополнительно передать
`domain_id`, `group_id`, `traffic_source_id`, чтобы переопределить значения из `.env`.
Пустые названия, неизвестные ISO-коды стран и недоступные справочники отклоняются.

Последовательность: проверить справочники → создать **выключенную** кампанию с ротацией
по позиции → создать геопоток с редиректом на Google → создать общий поток с одним
оффером (100%) → включить кампанию → сохранить локальную кампанию и результат операции.
Успешный ответ 201 содержит ID кампании, ID потоков и tracking URL.

Повтор с тем же UUID и тем же телом возвращает прежний результат (200) без новых
запросов в Keitaro. Другое тело с тем же UUID возвращает 409. Для новой операции нужен новый UUID.

### Частичные сбои

- Журнал создаётся до первого изменения в Keitaro, этапы сохраняются до внешних запросов.
- `failed` — известная ошибка; уже созданная кампания остаётся выключенной, если включение
  ещё не началось. Её ID указан в журнале. Автоматического удаления нет.
- `unknown` — таймаут/сетевая ошибка/неоднозначный ответ при записи: операция могла выполниться.
- `pending` после перезапуска — незавершённая операция, которую также нужно проверить вручную.
- При сбое локального сохранения после внешнего запроса возвращается 503 с `operation_id`;
  последний сохранённый этап остаётся в журнале. Кампания к этому моменту может быть включена.
- Повтор этих операций с тем же UUID блокируется (409); автоматических повторов записей нет.

Для сверки используйте `remote_campaign_id` или уникальный alias
`adrobot-<UUID без дефисов>` в Keitaro. Перед запуском новой операции после сбоя проверьте
существование предыдущей кампании. Автоматическое восстановление пока не реализовано.

Текущий сервер рассчитан на локальную работу по `127.0.0.1`; пользовательская авторизация
и публичный деплой не входят в этот этап.

## Проверки

```sh
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pytest
uv run --locked alembic check
```

Тесты создают отдельные временные БД, применяют реальные миграции и не обращаются к Keitaro.
Проверяются миграции, готовность БД, транзакции, ограничения схемы, создание потоков,
идемпотентность, частичные сбои, неопределённый результат при таймауте, поиск офферов,
сохранение черновиков и архива, точная отмена, закрепления, округление долей и конкурентные правки.

## Миграции

```sh
uv run --locked alembic current
uv run --locked alembic revision --autogenerate -m "describe schema change"
uv run --locked alembic upgrade head
```

Сгенерированную миграцию необходимо проверить перед коммитом.
`alembic downgrade base` удаляет таблицы приложения и их данные — использовать только
для одноразовой тестовой БД. Тест обратной миграции выполняется именно на временной БД.
